# EXPLAINERS — 2D and 3D Interactive Explanations

## 1. Architecture

```
src/explainers/
  registry.ts                 # id -> () => import('./<id>/index.tsx')
  shared/                     # Slider, StepControls, Legend, Axis, useReducedMotion, useInView, SceneShell
  <id>/
    index.tsx                 # React island (2D or 3D)
    data.json                 # real exported data OR toy data (flagged in README)
    poster.png                # static fallback, generated by scripts/posters.ts (Playwright screenshot)
    README.md                 # what it shows, source, simplifications, verification record
    <id>.test.ts              # unit tests for any computed math
src/components/Explainer.astro  # used in MDX: <Explainer id="bwa-barycenter" />
```

`Explainer.astro` renders, in order:
1. `ExplainerFrame`: title, caption, "How to read this" toggle, text description for screen readers.
2. `poster.png` immediately (no layout shift; fixed aspect ratio box).
3. The island with `client:visible`, which replaces the poster once loaded **and** only if: WebGL available (3D), `prefers-reduced-motion` is not `reduce` (for animated ones; static interactive is fine), and the device is not in data-saver mode.

### 2D rules

- SVG + `d3-scale`, `d3-shape`, `d3-array` (import individual modules). Canvas only when > 2,000 marks.
- Responsive with `viewBox`; text never below 12 px at 360 px wide.
- Controls are native `<input type="range">`, `<button>`, `<select>` with visible labels; value changes announced via `aria-live="polite"`.
- Step-through mode (Step 1 / 2 / 3 buttons with a short caption per step) instead of scroll-jacking.

### 3D rules

- `@react-three/fiber` + `@react-three/drei`. Import only from inside the island file.
- `<Canvas frameloop="demand" dpr={[1, 2]}>`; invalidate only on interaction or animation; stop when off-screen / tab hidden.
- `OrbitControls` with damping, zoom limits, no pan by default; reset-view button; keyboard alternatives (arrow keys rotate, +/- zoom, R reset).
- Background `#09318d` or `#061f5c`; primary geometry white; highlighted element pink (`#fd91cc`), optionally emissive.
- Labels via drei `<Html>` (real DOM text, readable by screen readers) — not baked into textures.
- Assets: glTF/GLB, compressed (meshopt or Draco), ≤ 1.5 MB per scene. Molecules: load PDB files with a lightweight parser, or use a free viewer (3Dmol.js / Mol*) inside the island.
- No post-processing (bloom etc.) unless measured cost is < 2 ms/frame on a mid-range laptop.
- Canvas has `role="img"` + `aria-label`; full text description sits below it.

### When to use 3D

| 3D is justified | 3D is not justified (use 2D) |
|---|---|
| Geometry that is truly 3D: molecules, crystal lattices, NV-centre orientations, Bloch sphere, 3D cluster/percolation lattices | Pipelines, flowcharts, timelines |
| Surfaces computed from real data (e.g. a measured loss/accuracy grid) | Bar/line charts |
| Real 3-D embeddings (PCA/UMAP of real activations) | "Neural network" decoration |

For projects with no inherently 3D content, the 3D explainer is a **System Map**: the real architecture shown as layered blocks (UI → services → models → data), with animated particles along the real data flows; clicking a block shows what it does. This represents the actual system, so it is honest.

## 2. Fidelity protocol (must pass before `verified: true`)

1. **Source anchor** — README names the exact paper section/figure/table, report page, or code file the explainer represents.
2. **Data provenance** — either (a) real data exported from Muja's experiments, with the export script path, or (b) toy data, and the explainer shows a visible label: *"Illustrative example — not experimental results."* Mixing the two in one figure is not allowed.
3. **Math check** — every formula computed in the browser has a unit test against a reference value (hand-computed, from the paper, or from Muja's Python code). Tests live next to the explainer.
4. **Simplification note** — README and the "How to read this" panel state what is simplified.
5. **No invented numbers** — no accuracy, speed-up, p-value, or ranking appears unless it is in the source anchor.
6. **Muja sign-off** — Muja reviews and sets `verified: true` in the content file. Unverified explainers show a "Draft" label in dev and are **not rendered in production**.

If Claude Code cannot determine how a method works from the provided material, it must stop and ask Muja for the paper/code — never fill gaps with a generic diagram.
